# Folder layout and architecture conventions

Type: grilling
Status: resolved
Blocked by:

## Question

How is the project organised so agents and editor users both make fewer mistakes? Decide: by-feature vs by-type folders; file/node/class naming (Godot style guide); which autoloads exist and the rule for adding one; scene composition rules (scenes self-contained, "call down, signal up"); when a global signal bus event is allowed vs a local signal; how `.tscn` files are edited (editor vs agent text edits) and the merge-conflict policy.

## Answer

- **Layout, by feature:** `addons/` (vendored plugins, pinned, never hand-edited), `core/<system>/` (one folder per autoload), `ui/` (main menu, settings screen, Theme, shared widgets), `game/` (the example game scene, replaced on jam day), `shared/` (cross-feature assets: soft-look environment, toon shader, fonts, music/SFX), `test/`. A file lives in the folder of the only feature that uses it and moves to `shared/` once a second feature needs it.
- **Naming:** the official Godot GDScript style guide, verbatim: snake_case folders/files, PascalCase nodes and `class_name`, snake_case funcs/vars, CONSTANT_CASE, `_private`, past-tense signals (`piece_placed`). A scene and its script share a base name and sit side by side (`main_menu.tscn` + `main_menu.gd`). Use `class_name` only when another script refers to the type by name (custom Resources, components, `is` checks, typed vars).
- **Static typing is enforced:** the `untyped_declaration` warning is set to **Error** in `project.godot`. Inferred types (`:=`) count as typed.
- **Autoloads:** `Events` (the signal bus), `Audio`, `SceneFlow`, `Settings`, plus the plugin's `LimboConsole`. Their internals belong to the core-systems design. A new autoload is allowed only for a service that must outlive a scene change, or that has exactly one instance game-wide. It lives in `core/<name>/`, never reaches into the current scene, and gets listed in `CLAUDE.md`.
- **Scene composition:** call down, signal up. No `get_parent()`, `../` or `/root/...` paths. A scene refers to its own nodes through `%UniqueName`. Outside dependencies come in through `@export` vars or a setter the parent calls. Every scene instantiates on its own without errors, so it can be F6-run in the editor and loaded in a gdUnit4 test.
- **Bus vs local signals:** local signals by default. `Events` carries only broadcast facts: past-tense, typed params, a `##` doc comment each, all declared in `events.gd`. Commands to a service are direct autoload calls (`SceneFlow.go_to(...)`, `Audio.play_sfx(...)`), never `*_requested` bus signals.
- **Editing `.tscn`:** agents may hand-edit any `.tscn` as text, visual properties included. Safety rules: never invent or copy a `unique_id` (leave it out; Godot adds one on the next save); reference resources by their existing `uid://`; run the headless load check after every edit. `PackedScene.pack()` is only for bulk generation (it rewrites ids). UI is built from Containers + a shared Theme, never hand-placed anchors and offsets, so text edits to it stay predictable. After any visual change, the agent checks the result itself with windowed frame capture (`--write-movie`, Mac only, see [headless research](../research/02-headless-godot-and-mcp.md) §1.4). When the change is about *feel* (soft look, lighting, camera), its handoff says "needs a visual check" and names the scene. Whether an MCP replaces or adds to frame capture is decided in ticket 07. Tuning by eye in the editor is recommended, not required.
- **Merges:** Godot has no official scene-merge policy ([VCS docs](https://docs.godotengine.org/en/stable/tutorials/best_practices/version_control_systems.html) only call its files "mostly mergeable"). Prevention: small composed scenes, one person (and their agent) per scene at a time, claimed in team chat, and pull/rebase only with the editor (or at least the affected scenes) closed, because the editor overwrites pulled changes when it saves its in-memory copy. For a conflicted `.tscn`/`.tres`: take one side whole (`git checkout --ours/--theirs`), redo the other change, run the load check. `project.godot` is INI and can be hand-merged. Use Godot's generated `.gitattributes`/`.gitignore` (LF, `.godot/` ignored); `.tscn` stays a text merge, no `merge=binary`.
- **Tests:** `test/` mirrors the `res://` path of what it tests, files named `<name>_test.gd` (e.g. `core/audio/audio.gd` → `test/core/audio/audio_test.gd`). The Web preset's `exclude_filter` drops the folder.
- **Assets:** no Git LFS. `.blend` sources stay out of the repo, with the modeller. Commit exported `.glb` only: importing `.blend` directly needs Blender installed, which would break headless import in CI and for every teammate without it. Question or compress any single asset over about 10 MB.
